01 · The lock

Three moves close every exit

123 lines of Solidity. The trick is not what the contract does — it is what it cannot do.

1

Hold & approve

FirmQuote holds the tUSDC collateral and approves the Somnia BinaryPool. The funder's wallet only ever funds the contract.

2

Rest as the owner

The contract calls placeBinaryOrder, so the order's owner is the contract — not any wallet.

3

No way to ask

No cancel function, no reduce function, no operator ever granted. The pool will only take instructions from an owner that cannot give them.

Every withdrawal path and why it is closed
Withdrawal pathWhy it is closed
cancelOrder(uint128) Owner-only. Any other caller — including the funder — reverts IncorrectSender 0xf5e39c1f. Proven above.
cancelOrderFor(owner, id) Needs an operator the owner approved. FirmQuote never grants one — there is no code path that could.
reduceOrderFor(owner, id, qty) Per-user approval only, no system allowlist. Same closed door.

The quote stands until a taker fills it or its mandatory expireTimestampNs lapses. Two exits — neither of them is "the maker changed their mind."

forge test — 42 tests, 0 failures. Seven of them assert the absence of every withdrawal selector from FirmQuote's ABI: the lock is tested as a missing feature, because it is one.

02 · What this makes possible

A book where every level tells you if it can run away

Designed · not built yet

Order.owner is readable on-chain. That means every price level can be typed by who owns it — the layer rampart's lock exists to enable. What follows is the design, stated plainly so it cannot be mistaken for a shipped feature: none of it is built.

Firm

Owner is a contract whose EXTCODEHASH is attested, still inside its lock window.

Claim: this depth cannot be withdrawn.

Pullable

Owner is a wallet.

Claim: this depth can vanish in one block.

Unverified

Owner is a contract nobody attested.

Claim: none. No claim is made — and that refusal is the point.

UNVERIFIED is load-bearing. A naive "owner is a contract → firm" check is forgeable: a hidden cancel, an upgradeable proxy, a DELEGATECALL, or an operator granted after resting would all fake FIRM. Under attestation an attacker can only mint UNVERIFIED depth — which renders as exactly what it is.

Firmness is a horizon, not a badge: a quote is firm only until min(unlockAt, order expiry) — a countdown, never a static label. The observable this unlocks — percent of the book that cannot be withdrawn — exists on no other exchange: Polymarket, Kalshi and every CEX keep resting orders as signed messages inside a private matching engine, with no on-chain owner to inspect. rampart will compute that number only when the classifier exists. No number is claimed today.

Why it was run twice — and why the second run is the honest one

The first order (tx 2) crossed the book and filled instantly — the limit was 0.50 and there were asks below it. Cancelling a filled order proves nothing: it fails for everyone and says nothing about firmness. So the run was repeated at 0.01, far below the touch, where the order genuinely rested:
